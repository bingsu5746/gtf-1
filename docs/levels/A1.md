# A1 "First Trace" 레벨 기획서 (초안)

**[검토]** 표시는 연우님이 정해 줘야 하는 부분, **[확인 필요]**는 연우님 PC의 원작 덤프나 게임 테스트로 확인할 부분이에요.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 이야기 | 신호를 처음 추적한다. 연락이 끊긴 앞선 팀의 첫 흔적을 찾는다. |
| 주 목표 | HSU 샘플 채취 |
| 보조 / 추가 목표 | 없음. 첫 레벨이라 단순하게 가요. |
| 콤플렉스 | 채굴 시설 (지금 값: ComplexResourceData 30, 원작 R1A1 그대로) |
| 예상 시간 | 15분 안팎 (지금 값: EstimatedDuration 930초, 원작 R1A1 그대로) |
| 처음 나오는 적 | 스트라이커, 슈터, 스카우트, 빅 스트라이커 |
| 플레이 느낌 | 조용히 잠입. 적을 깨우지 않고 지나가는 법을 익히는 레벨 |

## 2. 지금 상태 (mod/SIGNAL 기준)

A1은 원작 R1A1을 그대로 가리키고 있어요. 이름(PublicName)만 "First Trace"로 바꿨어요.

| 필드 | 지금 값 | 뜻 |
| --- | --- | --- |
| LevelLayoutData | 495148404 | 원작 R1A1의 구역 구성 |
| ObjectiveData.DataBlockId | 166 | 원작 R1A1의 목표 |
| 목표 위치 | 구역 LocalIndex 3, 구역 끝 쪽 | |
| LightSettings / FogSettings | 36 / 139 | 원작 R1A1의 조명과 안개 |
| EnemyPopulation | 1 | DefaultPop |
| ExpeditionBalance | 1 | Normal 자원량 |
| BuildSeed | 333 | 맵 모양을 정하는 시드 |

원작 블록을 직접 고치면 원작 R1A1도 바뀌어요. 그래서 레이아웃(495148404)과 목표(166)를 **새 번호로 복사해서** 고쳐요.

## 3. 구역 구성

구역 번호는 LocalIndex예요.

**원작 R1A1 레이아웃 확인 결과 (2026-10-25, 원작 덤프):** 구역은 4개인데, 일자로 이어지지 않고 갈라져 있어요.

| 구역 | 어디서 이어짐 | 크기(CoverageMinMax) | 들어가는 문 (ChainedPuzzle) | 조명 | 들어 있는 것 |
| --- | --- | --- | --- | --- | --- |
| 0 | 엘리베이터 | 50~60 | 없음 | 18 | 터미널 1 |
| 1 | 구역 0 | 50~100 | 12 "Small Cluster x2 - Alarm" | 36 | 터미널 1 |
| 2 | 구역 1 | 5~10 (아주 작은 막다른 방) | 4 "Single x1" (알람 없음) | 56 | 없음 |
| 3 | **구역 0** | 50~90 | 14 "Small Cluster Separated x4 - Alarm" | 0 | HSU 3, 시체 4, 터미널 1 |

- 우리 계획(0→1→2→3 일자 진행)과 달라요. 계획대로 하려면 복사본에서 구역 3의 BuildFromLocalIndex를 0→2로 바꾸고, 구역 2를 보통 크기(예: 40~70)로 키워요. 이렇게 하면 맵 모양이 원작과 달라져요. **결정(2026-10-25):** 계획대로 일자 진행(0→1→2→3)으로 바꿔요. 연우님이 가장 좋은 방법으로 정해 달라고 하셔서, 이야기 흐름(첫 탐색 → 흔적 → HSU)이 순서대로 나오는 쪽을 골랐어요.
- 원작 자원 배율은 구역 0: 0.33, 구역 1·3: 1.0, 구역 2: 0.5예요. 4장의 0.75는 구역 1~3에 적용해요.
- 원작에는 터미널 로그가 하나도 없어요. 로그 1, 2는 새로 넣어요.

| 구역 | 역할 | 들어가는 문 | 적 | 이야기 장치 |
| --- | --- | --- | --- | --- |
| 0 | 착륙 지점 | (엘리베이터) | 없음 | Warden 브리핑 |
| 1 | 첫 탐색 | 보안 문, 스캔만(알람 없음) | 잠든 스트라이커, Easy | |
| 2 | 앞선 팀 흔적 | 보안 문, Class I 알람 | 잠든 스트라이커와 슈터, Easy | 앞선 팀 시체, 터미널 로그 1 |
| 3 | HSU 구역 (목표) | 보안 문, Class II 알람 | 잠든 적 Medium, 빅 스트라이커 1, 스카우트 1 | 터미널 로그 2, HSU |

- 알람 후보: Class I(ID 7), Class II(ID 12). 덤프 확인: 7은 "Single x1 - Alarm", 12는 "Small Cluster x2 - Alarm"이에요. 알람 없는 스캔은 원작 구역 2에 쓰인 4 "Single x1"을 써요.
- 스카우트는 구역 3에 하나만 둬요. 은신 실패의 대가를 처음 보여 주는 용도예요.
- **샘플 채취 알람:** 원작 목표 166을 확인해 보니, 샘플을 뽑기 전에 HSU 스캔(ChainedPuzzleToActive 10 "HSU_Scan")을 하고, 샘플을 뽑은 뒤 탈출 단계에서 알람 웨이브(WavesOnGotoWin: 웨이브 설정 5 "Exit Trickle 3-8 S", 적 구성 1 "Original Baseline")가 나와요. 탈출 지점에서는 스캔 11 "ExpeditionExit_Scan"을 해요. 이 설정을 그대로 쓰고, 테스트해 보고 조절해요.
- **탈출:** 샘플을 뽑은 뒤 엘리베이터로 돌아가요. 돌아가는 길에 깨어난 적이 몰려오는 게 A1의 마지막 긴장 포인트예요.

## 4. 난이도와 자원

- 자원 배율(HealthMulti, WeaponAmmoMulti, ToolAmmoMulti): 0.75. 첫 레벨이라 하드코어 범위(0.5~0.75)에서 가장 넉넉한 값이에요.
- 시작 상태: 체력과 탄약 100%로 시작(SpecialOverrideData 그대로).
- 적 점수: 테스트하면서 맞춰요. 4명이 조용히 움직이면 싸움 없이 지나갈 수 있는 정도가 목표예요.

## 5. 분위기

- 안개: 엷은 안개. 지금 설정 139는 "Fog_light_with_soft_layer_R1A1"(엷은 안개, 낮게 깔린 층)이라 계획과 맞아요. 그대로 써요. (확인 완료)
- 조명: 어둡지만 손전등 없이도 길은 보이는 정도. 레벨 전체 조명 36은 "Monochrome_iceblue"(푸른 단색)예요.
- 구역 3에 들어서면(EventsOnEnter) 낮은 소리 하나로 "신호"를 처음 들려줘요.
  - 원작 덤프의 소리 ID는 숫자뿐이고 이름이 없어요. 그래서 원작 레벨에서 쓰인 곳을 보고 후보를 골랐어요. 어떤 소리인지는 게임에서 들어 봐야 알아요. **[확인 필요: 게임 테스트]**
  - 후보 1: 469352613 (R8 B3에서 깨진 글자 경고와 함께 15번 쓰임)
  - 후보 2: 1064851100 (R8 B1 목표 시작 때 쓰임)
  - 후보 3: 2591647810 (R7 C2 터미널 명령 때 쓰임)

## 6. 이야기 문구 (영어, 초안)

앞선 팀 이름은 **ECHO**예요(2026-10-24 연우님 결정). 신호를 쫓다 사라진 팀이라 "메아리"라는 뜻이 어울려요.

**Warden 브리핑 (RoleplayedWardenIntel)**

> Signal source unconfirmed. Previous team ECHO lost contact in this sector. Locate HSU, extract sample, return. Do not engage unless necessary.

**레벨 설명 (ExpeditionDescription)**

> A repeating signal has been detected deep in the mining complex. Team ECHO was sent to investigate. They did not return.

**터미널 로그 1 (구역 2) — ECHO_LOG_01**

> ECHO-2: Signal is stronger past this door. Sleepers here don't move like they should. They turn toward it. All of them.
> ECHO-1: Keep moving. Sample first, questions later.

**터미널 로그 2 (구역 3) — ECHO_LOG_02**

> ECHO-1: Sample taken. Warden says go deeper.
> ECHO-1: Nobody asked why the HSU was already open.

## 7. 데이터 작업 목록

연우님 PC의 원작 덤프가 있어야 하는 작업이 있어요. 순서대로 해요.

1. **ID 규칙 정하기:** SIGNAL에서 새로 만드는 블록은 원작과 겹치지 않는 번호를 써요. 제안: 레벨마다 1,000칸씩, A1은 101000~101999. 원작 블록 93종 모두 100000~199999 범위에 번호가 하나도 없어요. 안전해요. (2026-10-25 확인 완료)
2. **레이아웃 복사:** LevelLayout 495148404 → 101000. 구역 구성(3장)에 맞게 문, 알람, 적, 자원 배율, 시체, 터미널 로그를 고쳐요.
3. **목표 복사:** WardenObjective 166 → 101000. 목표 문구를 우리 이야기에 맞게 바꿔요.
4. **A1이 새 블록을 가리키게:** RundownDataBlock의 A1에서 LevelLayoutData와 ObjectiveData.DataBlockId를 새 번호로 바꿔요.
5. **문구 넣기:** 텍스트를 문자열로 바로 넣을 수 있는지, 텍스트 표(TextDataBlock)에 추가해야 하는지 터미널 로그 하나로 먼저 확인해요. **[확인 필요: 게임 테스트]**
   - 덤프 확인 결과: PublicName은 원래 문자열 칸이라, 10-23에 이름이 잘 보인 것만으로는 확인이 안 돼요. 레벨 설명(ExpeditionDescription), Warden 브리핑(RoleplayedWardenIntel), 터미널 로그 내용(LocalLogFiles의 FileContent)은 원작에서 모두 텍스트 ID(숫자) 칸이에요.
   - MTFO는 이런 칸에 문자열을 넣어도 받아 주는 것으로 알려져 있지만, 게임에서 한 번 확인해요. 안 되면 TextDataBlock에 새 텍스트를 추가해요(번호는 101000번대).
6. **파일 저장:** 고친 데이터블록 파일은 원작 블록까지 모두 담아서 `mod/SIGNAL/`에 저장해요(파일 통째로 덮어쓰는 방식).

## 8. 테스트 체크리스트

`python tools/deploy.py` → r2modman Default 프로필로 Start modded.

- [ ] SIGNAL 룬다운에 A1 "First Trace"가 보인다.
- [ ] 레벨이 오류 없이 시작된다.
- [ ] 구역 수와 문, 알람이 3장 표대로 나온다.
- [ ] 터미널에서 로그 두 개가 보이고, 문구가 깨지지 않는다.
- [ ] HSU 샘플을 뽑으면 알람이 울리고, 엘리베이터로 돌아가면 클리어된다.
- [ ] 4명(또는 봇 포함)으로 해 봤을 때 너무 쉽거나 어렵지 않다.
